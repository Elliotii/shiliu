# 拾流后续版本规划（现阶段整合版）

> **适用状态**：V4 / V4.1 已正式封存  
> **规划用途**：作为后续 V5 各 Version Session 的高层路线与边界基线  
> **规划性质**：冻结总体方向，不冻结具体 Schema、框架选型和实施细节  
> **项目优先级**：求职简历旗舰项目优先，同时保留完整产品能力演进空间  
> **形成日期**：2026-07-30

---

# 0. 当前起点

拾流当前已经完成：

```text
V4
Complete Grounded RAG
+
Independent Agentic Search
+
Stable Citation
+
Transcript-only Grounding
+
Fast / Deep 产品入口
+
Trace / Eval / UI

V4.1
Shared Answer Boundary Hardening
+
Deterministic Deep DecisionView
+
Context Token Reduction
```

因此，后续版本不再继续清理 V4 Deferred，也不再围绕固定 RAG 或一次性 Agentic Search 做增量修补。

拾流下一阶段的核心变化是：

```text
一次有引用回答
        ↓
可持续、可恢复的研究任务
        ↓
可复用、可更新的个人研究知识库
        ↓
理解用户与收藏库的个性化研究 Agent
        ↓
基于真实经验、经过验证的搜索策略改进
        ↓
主动型长期知识伙伴
```

V5 的总体定位为：

```text
Durable, Personalized and Experience-evolving Research Agent
```

其目标包括：

- 长程研究任务；
- Checkpoint / Resume / Retry / Cancel；
- HITL；
- 持久 Memory；
- 理解用户当前关注与长期偏好；
- 理解收藏库结构和内容关系；
- 复用研究资产；
- 积累可验证的搜索经验；
- 在受控条件下改进 Search Skill / Policy。

# 1. 总体路线

```text
V5-A
Durable Recursive Research Runtime
可持久、可恢复、可递归审核的长程研究任务

        ↓

V5-B
Evidence-backed Personal Knowledge and Corpus Workspace
可追溯内容知识、研究资产、收藏库模型、用户状态与系统经验

        ↓

V5-C
Personalized Research Agent
让用户、收藏库和知识资产真正影响搜索、回答、路由和主动帮助

        ↓

V5-D
Controlled Experience-driven Search Policy Improvement
把重复成功与失败转化为经过对照验证、可回滚的搜索 Skill / Policy

        ↓

Post-V5
Proactive Knowledge Companion
长期研究线程、陈旧提醒、Project Radar、条件式 Reviewer
```

原有 V5-A / V5-B / V5-C / V5-D 路线保持完整。

范围控制通过以下方式实现：

```yaml
roadmap_scope:
  preserve_v5_a_b_c_d: true

execution_scope:
  active_goal_at_a_time: 1
  every_version_can_close_independently: true
  later_foundations_may_be_prelayed: true
  later_capabilities_cannot_be_claimed_early: true
```

即：

- 路线能力不主动删除；
- 实施时一次只推进一个正式 Goal；
- 每个版本均可独立封版；
- 可以提前铺设后续所需字段和事件；
- 不能提前宣称后续能力已经完成。

# 2. 五条跨版本演进主线

后续版本不能只理解为四组功能。整体架构由五条 Lane 共同演进。

## 2.1 Research Runtime Lane

```text
V4 Deep Search
→ ResearchTask
→ Checkpoint / Resume
→ Recursive Audit
→ HITL / Continuation
```

解决任务如何可靠持续运行。

## 2.2 Knowledge Lane

```text
Transcript Evidence
→ Grounded Fact
→ Research Artifact
→ Topic Page
→ Long-term Research Thread
```

解决收藏内容如何成为可追溯、可复用知识。

## 2.3 Personal and Corpus Intelligence Lane

```text
User Events + Research History + Collection Structure
→ Current Focus
→ Explicit Preference
→ Corpus Model
→ Knowledge Progress
→ Personalized Product Behavior
```

解决 Agent 如何逐渐理解用户和收藏库。

## 2.4 System Experience Lane

```text
Trace
→ Experience Record
→ Failure Attribution
→ Improvement Hypothesis
→ Candidate Skill
→ Active Skill
```

解决 Agent 如何逐渐知道怎样搜索。

## 2.5 Evaluation Lane

```text
Dataset
+ Environment
+ Rollout
+ Judge
+ Experiment Identity
```

确保每次改进都能被比较、重放、回滚和解释。

# 3. 版本完成方式

每个版本设置两个不同节点。

## 3.1 Portfolio-ready Milestone

表示：

- 已形成完整用户闭环；
- 已具备稳定演示；
- 有真实 Case 和技术证据；
- 已足以写入简历并接受面试追问。

达到该节点不意味着停止开发。

## 3.2 Version Complete

表示：

- 该版本全部正式 Goal 已完成；
- 回归、风险和限制已记录；
- Closeout 和 Git 封存完成；
- 可以正式进入下一版本。

这样既不因“简历项目”主动削弱能力，也不要求等全部长期路线完成后才开始投递。

# 4. 每个 Goal 的统一验收合同

```yaml
GoalCompletion:
  product:
    用户获得了什么新的真实能力

  contract:
    State、输入、输出、权威和权限边界是否明确

  reliability:
    中断、失败、恢复、重复动作和副作用是否正确

  evidence:
    是否通过真实 Case、前后对照或机械测试证明有效

  provenance:
    参考了哪些上游思想或代码
    拾流做了哪些修改
    哪些上游能力被明确拒绝
```

实施模式继续采用：

```text
一个 Goal
→ 明确合同和非目标
→ 上游机制审查
→ Codex 实现
→ 自动测试
→ 真实 Case
→ 失败审查
→ Closeout
```

拾流同时只保持一个正式活跃 Goal，但可以与 Pi 第二项目并行。

# 6. V5-A：Durable Recursive Research Runtime

## 6.1 产品命题

V4 Deep 解决的是：

```text
一次 /ask 请求
→ 多轮有界搜索
→ 返回一次 Grounded Answer
```

V5-A 要解决：

> 一个复杂研究目标如何跨进程、跨时间、跨人工决策持续存在，并根据中间结果不断审核和定向推进？

正式新增产品对象：

```text
/research
ResearchTask
```

V5-A 不是简单给 V4 Deep Graph 加 Checkpointer。

---

## 6.2 产品流程

```text
Create Research Task
→ Define Goal
→ Plan
→ Search and Inspect
→ Collect Evidence
→ Produce Provisional Synthesis
→ Audit Goal and Claims
→ Continue / Wait for Human / Stop
→ Final Synthesis
→ Save Result
```

---

## 6.3 两层 Research Loop

### Inner Research Loop

```text
Plan
→ Navigation
→ Transcript Search
→ Window Read
→ Evidence Collection
→ Provisional Synthesis
```

### Outer Goal Audit

```text
Required Aspect Audit
→ Claim–Evidence Audit
→ Conflict Audit
→ Missing Evidence Diagnosis
→ Targeted Continuation
```

Outer Audit 只允许根据当前已经取得的 Evidence 判断，不得用模型隐含知识补齐事实。

# 10. V5-B 的领域知识三层结构

参考 DeepTutor 的 L1/L2/L3 可审计 Memory 思想，但权威语义由拾流重新定义。

## 10.1 L1：Evidence and Events

```yaml

  - TranscriptEvidenceSpan
  - StableCitation
  - SourceVersion
  - RetrievalTrace
```

- 原字幕/ASR 仍是事实权威；
- Trace 和 Event 尽量 Append-only；
- L2/L3 不得覆盖或修改 L1。

```yaml
  confidence:
  verification_status:
  conflict_group_id:
```

每个 Fact 必须绑定 L1 Evidence。

## 10.3 L3：Research Synthesis

借鉴 WeKnora Auto-Wiki 的产品形态，但不复制企业知识平台。

示例：


- 显示旧结论是否 Stale；
- 保留不同观点；
- 用户批准、编辑或拒绝更新；
- 下钻到原始字幕。

# 12. Artifact Reuse：相似问题直接复用知识

这是 V5-B 的核心产品闭环，而不是附属功能。

```text
User Query
    ↓
Artifact Retrieval
    ↓
Scope Match
    ↓
Source Version / Corpus Snapshot Revalidation
    ↓
Valid + Complete
→ 直接复用 Artifact 回答

Valid but Partial / Stale
→ 增量搜索缺失或变化部分

Scope 不匹配
→ 将旧 Artifact 作为 Research Seed
→ 进入 Fast / Deep / Research
```

## 12.1 Direct Reuse

- 问题范围一致；
- Evidence 仍有效；
- Citation 和 Source Version 可验证。

不重新运行完整 Deep Search。

## 12.2 Incremental Refresh

- 大部分知识仍有效；
- 只处理新增视频、过期来源或缺失 Aspect。

## 12.3 Research Seed

旧 Artifact 提供：

- 相关视频；
- 已有事实；
- 冲突；
- 未解决问题；
- 有效搜索术语。

但仍执行新的研究。

Verified Knowledge Artifact 属于 V5 能力，因为它需要 Staleness、版本和复用语义，不适合放入 V4。

# 14. Current Focus 与 Knowledge Progress


# 23. V5-D：Controlled Experience-driven Search Policy Improvement

# 24. V4 与 V5-D 的区别

V4 已经能：

```text

```

但 V4 不会长期记住：

- 哪类问题容易遗漏反例；
- 哪种 Query Rewrite 在收藏库中更有效；
- 哪类任务需要来源多样性；
- 哪个停止条件容易提前停止；
- 哪种搜索路径在同类任务中反复失败。

V5-D 负责：

```text

```

# 36. GraphRAG 的位置

```yaml
GraphRAG:
  status: eval_gated_candidate
  default: do_not_implement
```

- Hybrid / Agentic Search 反复出现关系型多跳失败；
- 有稳定可维护 Schema；
- 每条关系能绑定 Evidence；
- 小型 Spike 在 Held-out Case 中有稳定增益；
- 增量建图成本可接受；

才进入正式路线。

目前可以借鉴 Query Decomposition 和 Relation-aware Evaluation，不需要实现完整 GraphRAG。
