# 拾流 Shiliu V2：阅读管理、Mark 与人工笔记

## Status

Approved

## Goal

将拾流从“视频摘要内容流”扩展为本地个人阅读管理工具，支持：

- 三档手动阅读进度；
- 独立的 `Mark` 标记；
- 归档及恢复；
- 一条视频多条人工笔记；
- 同一视频在多个收藏夹中显示多张卡片，但共用后台内容和用户状态。

本任务不得改变现有字幕、ASR、AI 总结和定时同步的核心处理逻辑。

## Context and Current State

### 仓库事实

- 当前版本为 `0.3.0`，本地运行于 `127.0.0.1:18520`。
- `videos.status` 当前表示字幕、摘要等后台处理状态，定义于 `src/shiliu/domain.py` 的 `VideoStatus`，不能复用于阅读进度。
- `videos.is_ignored` 已作为独立展示状态存在，`Database.set_ignored()` 不会修改处理状态。
- `video_source_memberships` 已实现“一条视频属于多个收藏夹”的后台关系。
- 当前首页 `Database.list_videos()` 以视频为中心查询，因此同一视频在“全部来源”中只显示一张卡片，并附带多个来源标签。
- 当前 `record_source_snapshot()` 能记录收藏关系新增、移除和重新出现，但重新收藏不会重新执行字幕或摘要处理。
- 当前首页模板位于 `src/shiliu/templates/index.html`，卡片交互集中在 `src/shiliu/static/app.js`。
- 当前 AI 输出中的 `detailed_notes` 在页面上显示为“深度笔记”，需要调整用户可见名称，避免与人工笔记混淆。
- 数据库当前 `SCHEMA_VERSION = 4`，升级必须兼容现有视频、忽略状态、字幕、摘要和收藏夹关系。

### 已确认的用户决策

- 阅读进度为 `未阅 / 正在阅读 / 已阅`，支持任意手动切换。
- 打开首页、摘要、原文或视频不得自动改变阅读状态。
- `Mark` 与阅读进度相互独立。
- 阅读进度使用三档滑动分段控件，`Mark` 使用紧邻它的独立开关。
- Mark 卡片使用明显的红橙渐变外框、立体外阴影和明确的 Mark 图标；卡片内部颜色、封面和内容背景保持不变。
- 已阅卡片整体内容降低透明度，视觉弱化程度与忽略接近，但不进入忽略的紧凑布局；Mark 外框不随内容一起变淡。
- 归档优先级高于忽略和 Mark。
- 保留现有忽略功能。
- 当前版本不支持批量操作。
- 一条视频支持多条纯人工笔记。
- 人工笔记支持基础 Markdown，以及点击编辑、失焦自动保存的轻量交互。
- 当前 AI 生成内容统一称为“AI 总结”；人工内容称为“我的笔记”。
- 同一视频在两个收藏夹中应显示两张卡片，但字幕、AI 总结、阅读状态、Mark、归档、忽略和笔记共用。
- 视频从所有收藏夹移除后退出日常内容流，但本地数据继续保留。
- 本版本不实现“已移出收藏夹”界面。
- P0 与 P0.5 作为同一个版本发布，但可以分阶段实现和验证。

## Scope

### 阅读进度

为每条视频保存一个视频级阅读状态：

```text
unread      → 未阅
in_progress → 正在阅读
read        → 已阅
```

要求：

- 默认状态为未阅；
- 支持三个状态之间任意切换；
- 只允许用户主动修改；
- 多收藏夹中的同一视频共用阅读状态；
- 页面使用三档分段滑动控件展示和修改。

### Mark

为每条视频保存独立的 Mark 状态：

```text
is_marked
marked_at
```

要求：

- Mark 不属于阅读进度；
- 任意阅读状态均可同时 Mark；
- Mark 不改变收藏夹顺序或首页排序；
- 提供 Mark 和取消 Mark；
- 提供 Mark 内容筛选；
- 多收藏夹卡片共用 Mark 状态；
- Mark 卡片显示明确图标，并通过最外层红橙渐变边框及立体外阴影明显区分。

### 归档

为每条视频保存独立归档时间：

```text
archived_at
```

要求：

- 归档是视频级操作；
- 归档后从首页、Mark 筛选和有笔记筛选中消失；
- 归档内容进入独立归档视图；
- 可以手动恢复；
- 手动恢复保留阅读状态、Mark、忽略状态和所有笔记；
- 归档不停止字幕、ASR、AI 总结或同步任务；
- 归档不删除封面、字幕、摘要、笔记或本地文件。

### 忽略状态兼容

继续使用现有 `is_ignored`：

- 未归档且忽略的视频继续缩小和弱化；
- 忽略不影响后台处理；
- 忽略和 Mark 可以同时存在；
- 同时存在时，忽略的紧凑展示优先，但必须保留 Mark 标记；
- 忽略且 Mark 的视频仍出现在 Mark 筛选中；
- 归档优先于忽略和 Mark，归档后卡片不出现在普通内容流。

### 人工笔记

一条视频可以拥有多条“我的笔记”。

每条笔记包含：

```text
id
video_id
content
created_at
updated_at
```

支持：

- 新增；
- 编辑；
- 删除；
- 自动保存；
- 创建时间；
- 修改时间；
- 基础 Markdown；
- 卡片显示人工笔记数量；
- 筛选所有有人工笔记的视频。

时间表示不使用独立字段。用户可以直接在笔记正文中写入类似 `13 : 20 这里值得再看` 的文本；半角冒号及其两侧空格只是人工书写约定，系统不解析、不校验、不转换，也不将其从句子中单独提取。

### 多收藏夹展示

后台继续以 `videos` 作为视频唯一实体，以 `video_source_memberships` 表示收藏夹关系。

展示规则：

- 同一视频存在于两个有效收藏夹时，在“全部来源”中显示两张卡片；
- 每张卡片显示自己的收藏夹名称；
- 每张卡片按照该收藏关系自己的收藏时间参与排序；
- 在单个收藏夹视图中，只显示该收藏夹对应的卡片；
- 两张卡片共用字幕、AI 总结、阅读状态、Mark、归档、忽略和人工笔记；
- 任意一张卡片修改视频级状态后，其他卡片必须反映同一结果；
- 卡片上的笔记数量相同；
- 同一视频不得重复调用字幕、ASR 或 LLM。

### 收藏关系变化

系统必须区分：

```text
持续存在
新增收藏夹关系
已移除关系重新激活
全部关系移除
```

规则：

1. 收藏关系持续存在时，定时同步不得解除归档或修改阅读状态。
2. 已归档视频新增收藏夹关系时，自动重新进入内容流。
3. 已移除后重新收藏时，自动重新进入内容流。
4. 如果视频仍有其他有效收藏夹关系，仅新增第二个收藏夹关系且视频未归档，不重置已有阅读状态。
5. 视频从零个有效收藏夹关系重新变为至少一个有效关系时，视为重新流入。
6. 重新流入时：
   - 解除归档；
   - 阅读状态重置为未阅；
   - 取消忽略；
   - 保留 Mark；
   - 保留人工笔记；
   - 复用已有字幕和 AI 总结；
   - 不重新调用 ASR 或 LLM；
   - 使用新的收藏时间更新展示顺序。
7. 如果收藏时间缺失，使用首次观察到该次重新流入的同步时间进行排序。
8. 视频从所有收藏夹移除后：
   - 不再出现在首页、Mark、有笔记和归档视图；
   - 后台视频、字幕、摘要、Mark、阅读状态和笔记继续保留；
   - 重新收藏后按照重新流入规则恢复。
9. 不处理“取消并重新收藏全部发生在两次同步之间，且收藏时间也未发生可观察变化”的不可检测情况。

## Non-goals

本任务不包含：

- 批量已阅、批量 Mark、批量归档或批量恢复；
- 根据打开页面、阅读原文或播放视频自动更新阅读状态；
- AI 笔记分类；
- AI 意图识别；
- AI 对人工笔记进行讨论或回复；
- 自动生成任务；
- Agent 执行笔记中的事项；
- 自动写入知识库；
- 笔记类型系统；
- 强制笔记模板；
- 笔记标签和文件夹；
- 笔记全文搜索；
- 笔记版本历史；
- 多用户或跨设备同步；
- “已移出收藏夹”页面；
- 对已处理视频重复调用字幕、ASR 或 LLM；
- 改变现有收藏夹原始排序；
- 对字幕、ASR、AI 总结 Prompt 或模型调用策略进行调整；
- 建立通用事件总线、插件系统或任务系统；
- 与本任务无关的整站页面重设计；
- 独立的笔记侧栏、抽屉或重型笔记工作台；
- 独立时间戳输入框、时间戳解析、时间戳校验和时间戳跳转；

实现不得包含上述 Non-goals 明确排除的能力。

## Users and Key Flows

### 更新阅读状态

```text
用户看到视频卡片
→ 操作三档阅读控件
→ 状态保存
→ 同一视频的其他收藏夹卡片同步显示该状态
```

### Mark 内容

```text
用户点击 Mark
→ 视频成为 Marked
→ 卡片获得标记及强化效果
→ 视频可通过 Mark 筛选找到
→ 收藏顺序不改变
```

### 归档与恢复

```text
用户归档任意一张视频卡片
→ 同一视频的所有普通卡片消失
→ 归档视图显示其有效收藏夹卡片
→ 用户恢复
→ 所有有效来源卡片恢复
→ 原状态和笔记不丢失
```

### 创建人工笔记

```text
用户为视频新增笔记
→ 在卡片底部输入正文
→ 点击其他位置时自动保存
→ 卡片笔记数量更新
→ 同一视频的其他来源卡片显示相同数量
```

### 重新收藏归档视频

```text
视频已归档
→ 新增到另一个收藏夹，或已移除关系重新激活
→ 同步识别成员关系变化
→ 自动解除归档
→ 重置为未阅并取消忽略
→ 保留 Mark、笔记、字幕和 AI 总结
→ 按新收藏时间进入内容流
```

## Behavioral Requirements

### 阅读控件

- 三档控件必须明确显示当前选项；
- 点击任意档位即可切换；
- 不要求按固定方向依次流转；
- 不使用原生连续数值滑块表达状态；
- Mark 开关必须独立于三档控件；
- 归档必须是独立按钮，并紧邻放在 Mark 右侧；
- 阅读状态请求失败时，页面必须恢复到服务端已保存状态或明确提示保存失败。

### Mark 视觉

- Marked 卡片必须同时显示 Mark 图标，并使用明显的红橙渐变外框；
- 不能只依赖颜色表达 Mark 状态；
- 忽略卡片仍须保留可识别的 Mark 标记；
- Mark 不得改变卡片内部、封面、内容背景或文字颜色；
- Mark 增加有立体层次的外阴影，但不得改变卡片内部内容样式。

### 已阅视觉与完整总结收起

- 阅读状态切换为已阅后，卡片内容降低透明度，视觉弱化程度与忽略接近；
- 已阅不触发忽略的缩小和紧凑布局；
- Marked 且已阅时，Mark 渐变外框仍保持清晰；
- 完整总结底部提供带向上箭头的“收起完整总结”按钮，点击后关闭当前展开区。

### 笔记自动保存

- 空白正文不得创建持久化笔记；
- 笔记以轻量单行列表放在卡片底部、“完整原文”入口之后；
- 笔记标题、正文和编辑框全部左对齐；
- 点击一条笔记正文后，原位置直接进入编辑状态；
- 点击笔记之外的其他位置使编辑框失焦，并触发自动保存；
- 不提供独立保存按钮；
- 每条笔记的写入请求必须串行，防止旧请求覆盖较新的文本；
- 正常保存不要求常驻显示“保存中”或“已保存”，保存失败必须提供轻量错误提示；
- 保存失败不得清空用户当前输入；
- 编辑笔记不改变笔记原有排序位置；
- 笔记默认按创建时间稳定排序；
- 每条笔记占据一行或一个可换行的轻量行项目；
- 删除入口仅使用该行末尾的小型删除图标，不显示“删除”文字；
- 点击删除图标后直接硬删除，不增加确认弹窗，本版本不提供回收站；
- 新建入口使用轻量的加号图标，不使用大型按钮或独立面板。

### Markdown

- 数据库存储用户输入的原始 Markdown；
- 展示时渲染段落、列表、链接、强调和代码；
- 不执行用户输入的 HTML、脚本或事件属性；
- 编辑时允许显示 Markdown 源文本；
- AI 总结中的历史 `detailed_notes` 数据字段可以继续保留，但页面不得称其为“AI 深度笔记”。

### 笔记中的时间文本

- 时间信息只是笔记正文的一部分，不设置独立字段；
- 用户可以按 `13 : 20 这里值得再看` 的形式人工书写，其中使用半角冒号并在冒号两侧保留空格；
- 系统原样保存并在句子中原样展示；
- 系统不识别分钟或秒数，不解析、不校验、不转换，也不生成跳转链接。

### 查询与排序

- 首页和常用筛选只返回未归档且至少存在一个有效收藏夹关系的视频卡片；
- Mark 筛选只返回 `is_marked=true` 的有效卡片；
- 有笔记筛选只返回至少存在一条人工笔记的有效卡片；
- 归档视图只返回已归档且至少存在一个有效收藏夹关系的卡片；
- 同一视频的多收藏夹卡片按各自成员关系排序；
- 筛选不得修改持久化顺序；
- 笔记数量必须在列表查询中聚合，禁止每张卡片单独查询一次笔记数量。

## Proposed Approach

### 数据模型

升级 SQLite Schema，新增视频级字段：

```text
reading_state TEXT NOT NULL DEFAULT 'unread'
reading_state_updated_at TEXT
is_marked INTEGER NOT NULL DEFAULT 0
marked_at TEXT
archived_at TEXT
```

新增 `video_notes` 表，通过 `video_id` 关联视频。

阅读状态必须使用受控枚举，数据库更新接口拒绝未知值。

### 查询模型

内容流查询从“视频中心”调整为“有效收藏夹成员关系中心”：

```text
video_source_memberships
JOIN videos
JOIN favorite_sources
LEFT JOIN note count
```

每一行成员关系形成一张卡片；共享状态仍来自同一条 `videos` 记录。

### 业务边界

状态和笔记操作通过一个轻量的阅读管理职责统一校验，避免将阅读逻辑写入字幕和摘要 Pipeline。

允许新增一个职责明确的本地模块，例如：

```text
library.py
```

它只负责：

- 阅读状态；
- Mark；
- 归档与恢复；
- 人工笔记；
- 收藏关系重新流入时的状态变更。

不得发展为通用工作流、事件框架或插件系统。

### 收藏关系事件

可以复用现有 `events` 表记录明确的成员关系变化，例如：

```text
favorite_membership_activated
favorite_membership_removed
```

事件只用于明确同步边界和测试，不得新增独立队列或常驻 Worker。

### 用户可见命名

```text
AI 总结
├── 一句话结论
├── 核心观点
├── 完整总结
├── 重要章节
├── 可执行事项
└── 相关链接

我的笔记
Mark
未阅 / 正在阅读 / 已阅
```

## Alternatives Considered

### 将 Mark 作为第四档阅读状态

不采用。否则无法表达：

```text
未阅 + Mark
正在阅读 + Mark
已阅 + Mark
```

### 使用 `follow` 命名

不采用。容易与关注 UP 主、订阅或自动追踪混淆。

### 每个收藏夹复制一份视频记录

不采用。会重复字幕、摘要、ASR、LLM 调用和笔记数据。

### 所有来源继续合并成一张卡片

不采用。用户已明确要求同一视频位于两个收藏夹时显示两份。

### 重新收藏后重新执行 AI 管线

不采用。已有字幕和总结可复用，并与当前“重新收藏不重复处理”规则冲突。

### 将人工笔记写入摘要 JSON

不采用。摘要是模型产物，人工笔记需要独立编辑、删除、时间和后续扩展能力。

## Data / API / Tool / Interface Changes

### 数据库

- Schema Version 从 4 升级；
- `videos` 增加阅读、Mark 和归档字段；
- 新增 `video_notes` 表及必要索引；
- 升级前继续使用现有数据库备份机制；
- 现有视频迁移为：
  - `reading_state=unread`；
  - `is_marked=0`；
  - `archived_at=NULL`；
  - 保留现有 `is_ignored`。

### 建议接口

```text
PATCH  /api/videos/{video_id}/reading-state
POST   /api/videos/{video_id}/mark
DELETE /api/videos/{video_id}/mark

POST   /api/videos/{video_id}/archive
DELETE /api/videos/{video_id}/archive

GET    /api/videos/{video_id}/notes
POST   /api/videos/{video_id}/notes
PATCH  /api/notes/{note_id}
DELETE /api/notes/{note_id}
```

状态修改必须以 `video_id` 为主键，不得以卡片或收藏夹成员关系为主键。

### 页面查询

页面至少支持：

```text
view=feed
view=marked
view=noted
view=archived
source=<source_id>
```

`source` 可以与 `feed`、`marked`、`noted` 和 `archived` 组合。

## Error Handling and Recovery

- 无效阅读状态返回 400，不写入数据库；
- 不存在的视频或笔记返回 404；
- 笔记正文为空时不创建记录；
- 自动保存失败时保留输入并显示失败状态；
- 归档、恢复、Mark 和阅读状态操作必须原子写入；
- 数据库迁移失败时不得继续启动到半迁移状态；
- 迁移前保留兼容当前机制的数据库备份；
- 同步不能确定收藏关系是否真正变化时，不得擅自解除归档；
- 已有摘要或笔记文件异常不得阻止用户恢复归档状态；
- UI 更新失败时允许刷新页面从数据库恢复真实状态。

## Acceptance Criteria

- 现有数据库升级后，视频、字幕、AI 总结、忽略状态和收藏夹关系不丢失。
- 所有现有视频默认显示为未阅。
- 阅读状态可在未阅、正在阅读、已阅之间任意手动切换。
- 已阅卡片内容明显降低透明度，但仍保留普通卡片尺寸和结构。
- 打开首页、完整原文或视频链接不会自动改变阅读状态。
- 页面提供三档分段滑动控件和独立 Mark 开关。
- 归档作为独立按钮显示在 Mark 右侧。
- 同一视频可以同时处于任意阅读状态和 Marked 状态。
- Marked 卡片显示 Mark 图标、红橙渐变外框和立体外阴影。
- Marked 卡片内部、封面、内容背景和文字颜色与普通卡片一致。
- Mark 不改变收藏夹顺序。
- Mark 筛选只显示有效且未归档的 Marked 卡片。
- 归档后，视频从首页、Mark 和有笔记筛选中消失。
- 归档视图能够显示和恢复归档视频。
- 手动恢复保留阅读状态、Mark、忽略和笔记。
- 忽略且 Mark 的视频保持紧凑显示、保留 Mark 标记并出现在 Mark 筛选中。
- 一条视频可以新增、编辑和删除多条人工笔记。
- 笔记以左对齐的轻量行列表显示在卡片底部、“完整原文”之后。
- 点击笔记正文在原位置进入编辑，点击其他位置后自动保存。
- 每行末尾只显示小型删除图标，点击后直接删除；新建入口为轻量加号图标。
- 笔记支持创建时间和修改时间，但不设置独立时间戳字段。
- 笔记行中的修改时间只显示到分钟，格式为 `YYYY-MM-DD HH:MM`，不显示秒和时区。
- 类似 `13 : 20 这里值得再看` 的内容作为普通正文原样保存和展示，不进行任何时间解析。
- 笔记支持安全的基础 Markdown 渲染。
- 完整总结底部可以通过向上箭头按钮直接收起。
- 卡片显示人工笔记数量。
- 有笔记筛选只显示至少有一条人工笔记的有效视频卡片。
- 同一视频位于两个收藏夹时，在全部来源中显示两张卡片。
- 两张卡片按各自收藏时间排序并显示各自来源。
- 两张卡片共用阅读状态、Mark、归档、忽略、笔记、字幕和 AI 总结。
- 对任意一张重复卡片操作后，其他卡片反映相同视频级状态。
- 已归档视频新增或重新激活收藏关系后自动恢复、重置未阅、取消忽略并保留 Mark 和笔记。
- 新增第二个收藏夹关系时，如果视频仍处于普通内容流且未归档，不重置阅读状态。
- 从所有收藏夹移除的视频退出日常视图，但后台数据不删除。
- 重新收藏不会重复调用字幕、ASR 或 LLM。
- 当前 AI 内容在页面统一称为“AI 总结”或“完整总结”，不出现“AI 深度笔记”。
- 实现不包含 Non-goals 明确排除的能力。

## Risks

- 当前首页是视频中心查询，改成成员关系中心后可能影响瀑布流排序和重复卡片布局。
- 同一 `video_id` 对应多个 DOM 卡片，前端若只更新当前卡片，可能出现同页状态不一致。
- 自动保存请求乱序可能覆盖较新笔记，必须按笔记串行。
- Markdown 渲染处理不当可能引入本地脚本注入。
- 归档恢复如果只判断“同步看见视频”，会导致每次定时同步错误恢复归档内容。
- 收藏关系没有可靠收藏时间时，只能使用观察时间近似排序。
- 多来源聚合笔记数量如果实现为逐卡查询，可能产生明显 N+1 查询。
- Schema 升级必须保护现有数据库和历史内容。

## Assumptions

- 拾流当前仍是单用户、本机使用。
- Mark、阅读状态、归档、忽略和笔记均为视频级状态。
- 同一视频在多个收藏夹的重复卡片只具有不同来源与排序信息。
- `is_marked` 是最终内部字段命名，页面使用 `Mark`。
- 笔记使用点击编辑、失焦保存，不使用按键停止计时的自动保存交互。
- Mark 外框的具体颜色值可以在实现时沿用现有主题选择，但不得改变已确认的视觉边界。

## Stop and Escalation Conditions

后续实现遇到以下情况必须停止并请求决定：

- 需要修改字幕、ASR、AI Prompt、模型调用或 launchd 逻辑；
- 需要引入新的第三方依赖、前端框架、ORM、数据库、队列或 Worker；
- 无法在不复制视频实体的情况下实现多收藏夹多卡片；
- 重新收藏必须重新调用字幕、ASR 或 LLM 才能满足实现；
- 数据库迁移可能丢失现有状态、摘要、字幕或收藏关系；
- Markdown 无法在现有依赖下安全渲染；
- 必须改变现有收藏夹排序语义；
- 自动恢复规则无法区分持续存在与可观察的收藏关系变化；
- 最终 UI 需要引入尚未确认的核心交互；
- 任一 Acceptance Criterion 无法满足；
- 实际复杂度需要把本任务扩展为通用知识库、工作流或 Agent 框架。
