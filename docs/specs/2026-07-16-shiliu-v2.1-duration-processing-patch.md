# 拾流 V2.1：时长分级处理与 LLM 费用保护补丁

## Status

Approved

## Goal

为现有视频级 Pipeline 增加基于视频时长的处理分级，降低长视频字幕校对和摘要产生的 LLM 成本，并在封面上显示视频时长。

本补丁属于 V2 的独立小版本，不进入、不修改尚未完成的 V3 Taxonomy Pipeline。

## Context and Current State

### 仓库事实

- 视频级处理由 `src/shiliu/pipeline.py:PipelineService` 编排。
- 当前所有已有字幕的视频默认依次执行字幕整理和摘要。
- 正式字幕整理、正式摘要和精修复核目前使用 `thinking=max`。
- `src/shiliu/llm.py:OpenAICompatibleProvider` 只有连接测试设置了 `max_tokens`，正常 Pipeline 调用没有输出保险。
- `src/shiliu/domain.py:FavoriteItem` 已包含 `duration_seconds`。
- `src/shiliu/bilibili.py:BilibiliAdapter.list_favorite_items()` 已从收藏夹列表解析时长。
- `videos.duration_seconds` 已存在，但收藏夹同步没有及时把列表时长写入视频记录。
- 当前真实数据库有132条活跃视频关系，其中19条已知时长、113条缺少时长。
- 自动 ASR 当前仅适用于5分钟以内视频；超过5分钟只能由用户手动触发。
- V3 使用独立的 `taxonomy_*` 表、`src/shiliu/taxonomy/` 和 `/taxonomy` 页面。
- Snapshot #1 已冻结，Hash 为：

```text

```

## Scope

本补丁必须完成：

1. 将默认视频处理边界改为8分钟和16分钟。
2. 所有 AI 字幕校对统一使用 DeepSeek V4 Flash。
3. Flash 字幕校对显式关闭 thinking。
4. 所有仍启用 thinking 的调用统一使用 `reasoning_effort=high`。
5. V4 Pro 只用于摘要和摘要复核。
6. 根据视频时长决定完整处理、仅摘要或仅保存原字幕。
7. 为模型调用设置宽松、按时长增长的输出保险。
8. 将收藏夹列表中的视频时长及时写入现有视频记录。
9. 对当前缺少时长的视频执行一次性补齐。
10. 在封面右下角显示视频时长。
11. 为正常跳过的长视频显示明确结果，不再显示成“等待可用内容”。
12. 保持现有自动同步、失败恢复、ASR 冷却和人工重试能力。

## Users and Key Flows

### 不超过8分钟且已有字幕

```text
读取视频时长和字幕
→ 保存原始带时间戳字幕
→ DeepSeek V4 Flash 无 thinking 校对原文
→ DeepSeek V4 Pro thinking=high 生成摘要
→ 正常完成
```

### 8～16分钟且已有字幕

```text
读取视频时长和字幕
→ 保存原始带时间戳字幕
→ 不调用字幕校对模型
→ 将原始字幕转换为内部临时摘要输入
→ DeepSeek V4 Pro thinking=high 生成摘要
→ 正常完成
```

此路径不生成或伪造 AI 整理原文。

### 超过16分钟且已有字幕

```text
读取视频时长和字幕
→ 保存原始带时间戳字幕
→ 不调用任何 LLM
→ 标记为正常完成
→ 页面显示“仅保存原字幕（时长策略）”
```

### 没有字幕

```text
≤5分钟
→ 保留现有自动 ASR 规则

>5分钟
→ 不自动 ASR
→ 显示“无字幕 · 未自动处理”
→ 保留“立即生成字幕”按钮
```

用户手动触发 ASR 后：

```text
≤8分钟
→ Flash 校对原文
→ Pro 摘要

>8分钟
→ 不生成 AI 整理原文
→ 直接生成 Pro 摘要
```

手动 ASR 是对默认时长策略的显式人工覆盖，但不改变自动 ASR 的5分钟上限。

## Behavioral Requirements

### 时长边界

统一使用整数秒判断：

```text
完整处理：duration_seconds <= 480
仅摘要：481 <= duration_seconds <= 960
仅保存原字幕：duration_seconds >= 961
```

恰好8分钟进入完整处理。

恰好16分钟进入仅摘要处理。

### 时长未知

当 `duration_seconds <= 0` 时：

- 不得将视频视为不超过8分钟；
- 应先尝试从收藏夹列表或单条视频详情补齐；
- 如果仍无法获得时长，不得调用 LLM；
- 视频进入可观察的人工处理状态；
- 页面显示“时长未知 · 未自动处理”。

### 模型路由

字幕相关阶段：

```text
transcript_cleanup
refined_transcript_cleanup
→ deepseek-v4-flash
→ thinking disabled
→ 不设置 reasoning_effort
```

摘要相关阶段：

```text
summary_generation
refinement_review
→ deepseek-v4-pro
→ thinking enabled
→ reasoning_effort=high
```

不再有任何视频 Pipeline 阶段使用 `reasoning_effort=max`。

连接测试不属于视频 Pipeline，不受本规则影响。

### 宽松输出保险

输出保险不得作为内容截断目标，只用于防止异常生成。

建议公式：

```text
Flash 字幕校对：
max_tokens = clamp(
    16384,
    ceil(duration_seconds / 60) × 3072,
    24576
)

V4 Pro 摘要或复核：
max_tokens = clamp(
    32768,
    ceil(duration_seconds / 60) × 4096,
    65536
)
```

其中：

```text
clamp(最小值, 计算值, 最大值)
```

要求：

- 保险值必须显式发送给 Provider；
- 达到保险上限视为异常输出；
- 不得自动扩大上限并再次计费；
- 应进入人工重试状态；
- 页面应显示“模型输出达到保险上限”；
- 用户手动重试仍使用相同保险，不自动翻倍。

### 8～16分钟的摘要输入

仅摘要路径必须：

- 保持原字幕顺序；
- 使用确定性代码把字幕片段转成摘要输入；
- 可以合并连续字幕行以减少格式噪声；
- 不得调用 Flash 或其他模型生成中间原文；
- 不得写入 `transcript.refined.*`；
- 不得把临时摘要输入显示为“AI 整理原文”；
- 原始带时间戳字幕文件仍正常保存。

### 超过16分钟的终态

已有字幕且超过16分钟的视频：

- 保存 `subtitle-raw.json` 和 `subtitle-raw.txt`；
- 不创建字幕整理 Stage；
- 不创建摘要 Stage；
- 使用现有视频粗粒度状态表达正常完成；
- 页面根据时长、原字幕存在和摘要不存在显示：

```text
仅保存原字幕（时长策略）
```

该状态不是失败、忽略、归档或需要重试。

### 手动与定时处理

- 时长策略同时适用于定时同步和立即同步。
- 8～16分钟的摘要结果是最终结果，不再因“立即同步”自动创建字幕精修任务。
- 不超过8分钟的立即同步仍可保留现有快速版与后续精修语义。
- 已有快速版但时长超过8分钟的待精修视频不得继续调用字幕精修模型；应保留现有内容并结束不再适用的字幕精修。
- 已完成视频不因安装本补丁自动重新处理。
- 用户点击“立即重试”时，重新按照当前时长规则路由。

### 时长写入与补齐

收藏夹扫描时：

- 对已经物化的视频更新 `duration_seconds`；
- 新建视频记录时立即保存收藏列表提供的时长；
- 不因补齐时长触发 LLM 或 ASR；
- 不改变收藏时间、收藏夹顺序或用户状态；
- `duration_seconds=0` 不得覆盖已有非零时长。

一次性补齐：

- 使用现有 Bilibili Adapter 读取当前启用收藏夹；
- 优先使用收藏夹列表已经提供的时长；
- 只有列表仍缺失时才读取单条详情；
- 对当前可见但缺少时长的视频执行一次补齐；
- 记录补齐前缺失数、成功数、仍缺失数；
- 不创建或修改 Snapshot；
- 不调用 LLM、ASR 或 Taxonomy Workflow。

### 封面时长显示

封面右下角增加时长标识：

```text
小于1小时：MM:SS
至少1小时：H:MM:SS
```

要求：

- 使用半透明深色背景和白色文字；
- 不覆盖现有右上角状态标识；
- 时长未知时不显示；
- 不显示 `00:00`；
- 已阅、忽略、Mark、归档状态不改变时长；
- 卡片缩小或降低透明度后，时长仍可辨认；
- 时长只作为信息展示，不可点击。

## Proposed Approach

在现有 `PipelineService` 中增加一个最小、纯函数式的时长决策：

```text
full
summary_only
subtitle_only
unknown_duration
```

该决策只负责选择现有处理路径，不建设通用策略框架。

处理方式：

- `full`：调用现有字幕和摘要阶段，但更新模型路由。
- `summary_only`：从原始字幕构造内存中的 `TranscriptResult` 或等价摘要输入，只执行摘要阶段。
- `subtitle_only`：保存原字幕后结束，不创建 LLM Stage。
- `unknown_duration`：停止自动处理并等待人工处理。

默认不新增视频状态枚举和策略数据库表。优先通过现有状态、时长和本地资产组合表达用户可见结果。

手动 ASR 的覆盖意图继续使用现有 `asr_jobs.trigger_mode=manual`，不新增第二套人工覆盖状态机。

## Alternatives Considered

### 所有视频继续完整处理

不采用。长视频字幕校对成本高，且用户已明确不需要默认完整处理。

### 所有摘要继续使用 `reasoning_effort=max`

不采用。当前摘要任务不需要默认使用最高思考强度，且已发生明显费用消耗。

### 完全不设置 `max_tokens`

不采用。模型最大输出远高于正常摘要需要，缺少异常费用保险。

### 使用固定很小的 Token 上限

不采用。可能导致思考内容耗尽预算，无法生成最终结构化结果。

### 为策略增加数据库表和通用规则引擎

不采用。当前只有8分钟和16分钟两档规则，不足以证明需要新架构层。

### 修改 V3 Snapshot 输入

不采用。本补丁只影响之后的视频处理结果，不得改变已经冻结的语料。

## Error Handling and Recovery

- 时长未知：停止 LLM，显示明确人工处理状态。
- 输出达到保险上限：不自动扩大预算，进入人工重试。
- 原字幕损坏或为空：不得进入摘要，沿用现有字幕失败处理。
- 8～16分钟摘要失败：沿用现有5分钟、30分钟、最多3次的 LLM 重试规则。
- HTTP 402、认证失败和模型不存在不得无限重试。
- 时长补齐失败不得阻断其他收藏夹同步。
- 单个视频补齐失败应记录错误并继续处理其他视频。
- 进程重启后不得把已完成的 `subtitle_only` 视频重新送入 LLM。
- 回滚本补丁不得删除已经补齐的时长或已保存的原字幕。

- 模型调用使用批准的动态宽松保险。

- 8～16分钟视频不生成 AI 整理原文文件。

## Risks

- B站收藏夹列表的部分时长可能缺失或格式异常。
- 动态保险过低可能让思考内容耗尽预算。
- 动态保险过高仍可能产生不必要费用，但风险显著低于384K默认上限。
- 8～16分钟原字幕噪声较大时，摘要质量可能低于经过校对的字幕。
- 现有快速版精修状态与新时长策略可能发生兼容冲突。
- 使用现有粗粒度状态表达 subtitle-only 结果可能不足以可靠恢复。
- 一次性回填读取大量详情可能触发B站频率限制。
- 未来新 Snapshot 的 A/B/C/D 分布可能因长视频不再生成摘要而变化；这属于未来语料真实可用性的变化，不得反向修改已冻结 Snapshot #1。

## Assumptions

- B站收藏夹列表返回的时长对大多数视频可靠。
- 原字幕可以通过确定性代码转换为摘要输入，不需要模型校对。
- V4 Pro `high` 足以完成当前结构化摘要。
- 24K 的 Flash 上限和64K的 Pro 上限对最长允许自动处理的视频足够宽松。
- 当前首页可以在不重构卡片布局的情况下增加右下角时长标识。
- 已有字幕且超过16分钟的视频暂不需要手动强制总结入口。
- 用户接受未来 Snapshot 根据当时实际已有摘要形成不同证据等级。

## Stop and Escalation Conditions

实施遇到以下情况必须停止并请求决定：

- 需要修改任何 `taxonomy_*` 表或 V3 Runtime/Eval 文件；
- Snapshot #1 的内容、Hash 或冻结时间发生变化；
- 必须新增数据库表或视频级策略字段才能可靠恢复；
- 必须新增视频状态枚举才能避免错误重跑；
- 时长补齐需要修改 Bilibili 上游依赖；
- 必须新增第三方依赖；
- 8～16分钟无法在不伪造整理原文的情况下复用摘要结构；
- 手动 ASR 覆盖无法通过现有 `trigger_mode` 可靠恢复；
- 动态保险无法区分正常输出与异常截断；
- 一次性时长补齐存在明显B站风控风险；
- 实际修改范围开始演变为通用策略框架；
- 任一 Acceptance Criterion 无法满足；
- 需要改变自动 ASR 的5分钟边界；
- 需要为超过16分钟已有字幕的视频新增人工总结功能。
