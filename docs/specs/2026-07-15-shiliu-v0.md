# 拾流 Shiliu V0：B 站收藏内容整理闭环

## Status

Approved

## Goal

构建一个 macOS 本地个人工具：

> 用户在手机端把视频加入一个明确的 B 站收藏夹后，拾流自动发现新增视频，获取 P1 字幕，通过两个阶段的大模型调用生成整理原文和结构化摘要，保存为本地内容资产，并通过轻量动态网页以瀑布流形式提供阅读。

V0 必须验证：

- B 站收藏行为能否成为稳定输入。
- 系统能否只处理启用后的新增视频。
- 字幕整理和摘要是否具有实际阅读价值。
- 后台同步、状态、重试和本地文件能否形成可恢复闭环。
- UI 是否能让用户快速浏览、展开笔记、查看完整原文和弱化不关心的视频。

## Scope

V0 必须交付以下能力。

### 本地应用入口

- `shiliu setup`：首次设置。
- `shiliu sync`：执行一次同步后退出。
- `shiliu serve`：启动本地 FastAPI 页面。
- `launchd`：每小时调用一次 `shiliu sync`。

### 首次设置

首次设置依次完成：

1. 选择本地内容目录。
2. 通过可见二维码登录 B 站。
3. 刷新并选择一个收藏夹。
4. 配置 OpenAI-compatible Base URL、API Key 和模型。
5. 测试模型实际生成能力。
6. 显示当前收藏夹数量。
7. 明确提示历史内容只建立基线、不处理。
8. 用户确认后建立基线。
9. 安装或启用每小时运行的 `launchd` 配置。

### 内容处理

- 扫描一个明确的收藏夹。
- 只处理首次建立基线后新增的视频。
- 每个 BV 视为一个内容项。
- V0 只处理和总结 P1。
- 获取标题、UP 主、简介、视频地址、封面和字幕。
- 保存字幕语言、人工/AI 来源及上游原始类型。
- 执行两个独立模型阶段。
- 生成结构化数据和 Markdown。
- 保存 SQLite 状态和本地文件。
- 取消收藏不删除本地成果。
- 删除后重新收藏不重复处理已完成视频。

### 动态本地页面

- 首页瀑布流。
- 视频处理状态。
- 标题、封面、一句话结论和 3～7 个核心观点。
- 卡片内展开深度笔记。
- 独立的完整原文研究工作台。
- 打开本地原始字幕文件。
- 忽略及恢复卡片。
- 立即同步。
- 查看失败信息和手动重试。

## Non-goals

- 音频下载、音频处理或 ASR。
- B 站自带 AI Summary。
- 多 P 字幕或多 P 摘要。
- 多收藏夹监控。
- YouTube、小红书、微博或其他平台。
- 自动打开或读取视频简介中的外部链接。
- 播放器及时间戳跳转播放。
- 每条核心观点与字幕片段的对应引用。
- 每句字幕显示时间戳。
- 完整摘要历史及 Prompt 版本恢复。
- 对已完成视频提供重新生成界面。
- Codex CLI、Claude Code CLI 或其他 Agent Runner。
- 自动执行“可执行事项”。
- 多 Agent、LangGraph、MCP、Hermes 或飞书。
- Redis、Celery、消息队列、Docker Worker 或云端任务系统。
- React、Vue 等 SPA。
- 多用户、账号系统、远程访问或 SaaS。
- 自动联网事实核查。
- 思维导图、闪卡、测验、语音播放或聊天问答。
- 人工修改 Markdown 后反向同步结构化数据。
- 模型调用成本上限。
- 长字幕分块和层级汇总。
- 英文字幕路径的真实视频集成验收；仅保留相应 Prompt 和结构入口。

实现不得包含 Non-goals 中明确排除的能力。

## Behavioral Requirements

### 收藏夹和新增定义

- V0 只绑定一个收藏夹。
- 首次扫描保存当前 BV 集合作为基线。
- 首次扫描不得拉取历史视频字幕、调用模型或生成卡片。
- 后续扫描使用 `platform + source_id + part` 作为内容身份。
- B 站 V0 身份为 `bilibili + BV + P1`。
- 收藏夹分页必须遍历至 `has_more=false`。
- 已完成内容重新加入收藏夹不得重复调用模型。
- 视频移出收藏夹时记录 `removed_at`，但保留文件和页面内容。

### P1 和字幕选择

配置保留：

```yaml
process_all_parts: false
```

V0 必须固定为 `false`。

字幕选择顺序：

```text
P1 中文字幕
→ P1 英文字幕
→ subtitle_pending
→ 最终 skipped_no_subtitle
```

字幕元数据至少保存：

```yaml
language: zh | en
source: human | ai | unknown
upstream_type: 0 | 1 | null
```

映射：

- `type=0` → `human`
- `type=1` → `ai`
- 其他值 → `unknown`，同时保留原始值

### 字幕等待

首次没有中英文字幕时：

- 状态变为 `subtitle_pending`。
- 自动同步中继续检查。
- 不进行音频或 ASR fallback。
- 达到字幕重试上限后变为 `skipped_no_subtitle`。
- 手动同步可以触发已到重试时间的检查。

### 封面

- 通过底层视频元数据读取 `pic`。
- 下载并保存为本地 `cover.jpg`。
- 封面下载失败不阻止字幕和摘要处理。
- 没有封面时页面显示无封面回退样式。

### 阶段一：整理原文

输入：

- 原始字幕段落及时间戳。
- 视频标题。
- 必要的字幕语言信息。

中文字幕处理规则：

- 保持原始时间顺序。
- 合并被字幕系统拆散的连续句子。
- 形成自然段。
- 补充标点。
- 轻度清理“嗯、然后、就是说”等语气词。
- 去除明显机械重复。
- 保留有意义的自我修正。
- 修正上下文明确的错别字和 ASR 错误。
- 不概括、不删减主要内容、不扩写。
- 无法确定的识别错误保留原样；只有影响理解的重要位置才标记 `[疑似识别错误]`。
- 根据内容生成分类标题。
- 不重新排列字幕。
- 同一主题再次出现时允许再次使用相同标题。
- 只在重要主题开头保留时间戳。

英文字幕：

- 原始带时间戳字幕文件保持英文。
- Prompt 预留把整理原文输出为中文的规则。
- V0 不要求用真实英文视频完成集成验收。

阶段一结构化输出：

```json
{
  "sections": [
    {
      "title": "分类标题",
      "start_seconds": 138,
      "paragraphs": ["整理后的原文段落"]
    }
  ]
}
```

`start_seconds` 非重要部分可以为 `null`。

### 阶段二：摘要生成

输入：

- 阶段一的中文整理原文。
- 视频标题。
- 视频简介。
- 从简介提取的全部 URL。

固定输出模块：

- 一句话结论。
- 3～7 个核心观点。
- 详细笔记。

按内容决定是否输出：

- 重要章节及时间戳。
- 涉及的模型、工具、框架、论文和项目。
- 可执行事项。
- 局限、争议和时效性提醒。

规则：

- 没有内容的可选模块不显示。
- 不输出“无”或空标题。
- 可执行事项只来自视频明确内容或能够直接推导的行动。
- 不读取外部链接内容。
- 简介中的全部 URL 必须在深度笔记末尾的“相关链接”中显示。
- 专有名词尽量保留英文。
- 摘要主体使用中文。
- 不生成虚构可信度分数。
- 时间戳只用于重要章节，不用于每条观点。

### 模型调用

V0 实现一个最小 `LLMClient` 接口和一个 `OpenAICompatibleProvider`。

配置项：

```text
Base URL
API Key
Model
```

协议基线：

- OpenAI-compatible Chat Completions。
- 不要求 Provider 支持 Responses API。
- 优先通过 `/models` 刷新模型列表。
- `/models` 不可用时允许手动输入模型名称。
- “测试连接”必须发送一次小型生成请求。
- 结构化输出由本地 Pydantic Schema 校验。
- Provider 不支持严格 JSON Schema 时，使用 Prompt 要求 JSON，再在本地校验。
- 关闭 SDK 自带自动重试，由拾流统一管理调用次数。

正常视频调用次数：

```text
阶段一 1 次
阶段二 1 次
合计 2 次
```

已成功阶段不得因后续阶段失败而重复执行。

### 状态

视频总体状态至少包括：

```text
discovered
subtitle_pending
transcript_processing
summary_processing
retry_wait
completed
skipped_no_subtitle
needs_review
```

显示忽略状态 `is_ignored` 与处理状态相互独立。

### 自动同步

- `launchd` 每小时启动一次 `shiliu sync`。
- 05:00–11:59 不执行自动同步。
- 12:00 恢复自动同步。
- 时间以本机时区为准。
- 页面“立即同步”不受暂停时间限制。
- `shiliu sync` 是一次性进程，完成后退出。
- `launchd` 不启动桌面 UI。
- 自动同步不依赖 `curl localhost`。
- UI 和 `launchd` 共用同一同步核心函数。
- 必须使用进程锁或 SQLite lease，避免 UI 和 `launchd` 重复同步。

### UI

首页卡片至少展示：

- 处理状态。
- 封面。
- 标题。
- 一句话结论。
- 3～7 个核心观点。
- 深度笔记按钮。
- 完整原文按钮。
- 忽略按钮。

新视频发现后立即出现卡片。尚未完成时只显示真实已有信息和状态，不生成占位结论。

完整原文工作台：

- 显示 Markdown 渲染后的整理原文。
- 不直接显示 Markdown 的 `#`、`-` 等语法符号。
- 分类标题可使用与正文不同的字号和颜色。
- 提供打开原始字幕文件的入口。
- 不要求字幕片段与视频播放器联动。

忽略后：

- 卡片保持原有排序位置。
- 只显示封面、标题和恢复按钮。
- 卡片高度缩小。
- 透明度适当降低，但标题必须保持可读。
- 不取消、暂停或删除后台处理结果。

### 文件和本地状态

默认位置：

```text
~/Library/Application Support/Shiliu/
├── shiliu.db
├── config.toml
└── logs/

~/Documents/Shiliu/
└── videos/
    └── BVxxxxxxxx/
        ├── cover.jpg
        ├── metadata.json
        ├── subtitle-raw.json
        ├── subtitle-raw.txt
        ├── transcript.json
        ├── transcript.md
        ├── summary.json
        └── summary.md
```

内容目录允许在首次设置时修改。

结构化 JSON 是页面和程序的事实来源。Markdown 是可阅读产物；V0 不承诺识别人工修改后的 Markdown。未来重新生成允许覆盖 Markdown，但重新生成界面不属于 V0。

## Proposed Approach

架构约束：

```text
launchd
→ shiliu sync
  → BilibiliAdapter
  → SQLite 增量比较
  → Transcript Pipeline
  → Summary Pipeline
  → 本地文件与事件

shiliu serve
→ FastAPI + Jinja2
→ 瀑布流和原文工作台
→ 立即同步与手动重试
```

内部职责应分离为：

- B 站读取与轨道选择。
- 同步和幂等状态。
- 字幕整理。
- 摘要生成。
- 文件渲染。
- UI 查询和用户操作。

内部事件至少包括：

```text
new_favorite
summary_completed
summary_failed
```

事件应写入 SQLite，而不是只存在于进程内存中。

“可执行事项”在 V0 只是文本数据。未来 Agent 接入通过新的执行模块读取该数据；V0 不创建 `AgentRunner` 实现。

阶段一和阶段二保持独立，因此未来可以增加“只重新生成摘要”或“重新整理并总结”，但 V0 不提供相关界面。

## Alternatives Considered

### Codex CLI 或 Claude Code CLI 直接总结

未选择。当前任务是稳定文本转换，不需要文件修改、Shell、工具调用或长程 Agent。CLI 会增加安装、认证、权限和子进程管理复杂度。

### Responses API

未作为兼容基线。V0 面向可配置 Base URL 的 OpenAI-compatible 服务，Chat Completions 的兼容范围更广。

### `bilibili-summary` 作为基座

未选择。其 ASR、完整 FastAPI、Provider 框架和 UI 超出 V0 边界。只参考产品表达，不作为运行依赖。

### React/Vue SPA

未选择。V0 使用 FastAPI、Jinja2 和少量原生 JavaScript即可满足瀑布流、卡片展开和工作台切换。

### 定时任务调用 localhost

未选择。同步核心必须能够在 UI 不运行时独立工作。

### 文件是否存在作为状态

未选择。SQLite 是处理状态来源，文件是产物。

### SQLite 最小表

`videos`：

- 内容身份、元数据和简介链接。
- 收藏状态。
- 字幕语言及来源。
- 当前总体状态。
- 文件路径。

`pipeline_stages`：

- 最后错误。
- Provider、模型和 Prompt 版本。
- 开始和完成时间。

`sync_runs`：

- 启动和结束时间。
- 运行方式：scheduled 或 manual。
- 成功或失败。
- 发现数量及错误摘要。

`events`：

- 事件类型。
- 视频 ID。
- payload。
- 创建和处理状态。

### 本地 HTTP 接口

仅服务本地页面和用户交互，需要覆盖：

- 初始设置。
- 首页数据。
- 单视频整理原文。
- 立即同步。
- 手动重试失败阶段。
- 忽略及恢复。
- 安全读取指定视频目录中的本地文件。

具体 URL 不在本规格中固定，但必须限制到受管理的数据目录，防止任意文件路径读取。

## Technical Constraints

- V0 目标为 macOS 单用户本地运行。
- Python 必须满足上游 CLI 的 `>=3.10`；当前验证环境使用 Python 3.12。
- Web 服务只监听 `127.0.0.1`。
- API 调用只能从 Python 后端发起。
- API Key 不写入浏览器 Local Storage、SQLite、日志或页面 HTML。
- API Key 优先保存到 macOS Keychain；配置文件只保存引用。
- B 站凭据沿用 CLI 的 `~/.bilibili-cli/credential.json`，权限必须为 `0600`。
- 日志不得包含 Cookie、API Key、完整请求头或未脱敏凭据。
- 封面和字幕下载必须设置超时。
- 不得静默截断字幕；若上下文超限，进入 `needs_review/context_too_large`。
- 正式分发前必须重新评估 `bilibili-api-python` 的 GPL 许可证影响。

## Change Boundary

### 允许新增或修改

当前没有正式应用结构，因此允许新增：

- 根级 Python 项目配置。
- 一个正式拾流 Python package。
- CLI 入口。
- FastAPI/Jinja2 页面与静态资源。
- SQLite schema 和迁移初始化。
- `launchd` plist 模板及安装逻辑。
- 正式单元测试和集成测试。
- 与 V0 直接相关的配置、Prompt 和 Markdown 模板。

具体 package 路径必须在实现开始时根据根级项目配置确定，不能假装已有路径。

## Complexity Budget

V0 最多允许：

- 一个本地 Python 应用进程模型。
- 一个 SQLite 数据库。
- 一个 FastAPI/Jinja2 本地 UI。
- 一个 `launchd` 定时入口。
- 一个 OpenAI-compatible Provider。
- 一个当前需要的 `LLMClient` 抽象。
- 普通 Python 状态机和持久化事件。

禁止为了未来可能性预建：

- 通用 Provider 插件系统。
- Agent Runner 框架。
- DAG 引擎。
- 消息队列。
- Worker 池。
- 通用多平台 Adapter Registry。
- 完整事件总线。
- 多层 Repository/Service 抽象套件。

任何新增依赖都必须直接服务于已列出的 V0 Acceptance Criteria。

## Error Handling and Recovery

### LLM 阶段

每个阶段最多尝试 3 次：

```text
首次调用
→ 5 分钟后可重试
→ 30 分钟后可再次重试
→ needs_review
```

实际执行发生在下一个符合条件的自动同步或立即同步中。

可重试：

- 网络错误。
- 超时。
- HTTP 408、429、5xx。
- 空响应。
- JSON 解析失败。
- Schema 校验失败。
- 核心观点数量不符合要求。

不自动重试：

- API Key 无效。
- 权限不足。
- 模型不存在。
- Base URL 或 Provider 配置错误。

阶段一成功、阶段二失败时，只重试阶段二。

### B 站和字幕

- 登录失效：进入 `needs_review/authentication_required`，提示重新扫码。
- 403/412：记录上游限制，按可重试错误处理。
- 不存在或权限受限视频：保留错误证据，不盲目映射为永久不存在。
- 无字幕：进入 `subtitle_pending`，达到上限后 `skipped_no_subtitle`。
- 封面失败：保留无封面卡片，不影响主流程。

### 手动处理

- `needs_review` 页面提供错误详情及手动重试。
- 手动重试开启新的阶段尝试周期，但保留旧错误记录。
- V0 不自动回滚或删除已经成功的阶段产物。

## Acceptance Criteria

- 首次设置能完成二维码登录、收藏夹选择、模型配置、连接测试和基线确认。
- 首次基线中的历史视频不拉字幕、不调用模型、不生成内容卡片。
- 基线后新增视频能在一次同步中被发现且不重复入库。
- V0 只处理 P1。
- 中文字幕优先于其他轨道。
- 字幕来源正确记录为 human、ai 或 unknown。
- 没有合格字幕时不使用音频或 ASR。
- 封面成功时保存并显示；封面失败不阻断流程。
- 原始字幕以带时间戳本地文件保存。
- 阶段一保持字幕顺序，只做允许的轻度整理。
- 阶段一输出分类标题、自然段和少量重要时间戳。
- 阶段二输出一句话结论、3～7 个核心观点和详细笔记。
- 可选模块没有内容时不显示。
- 简介中的全部 URL 出现在深度笔记末尾，系统不访问其内容。
- 正常视频仅产生两次模型生成调用。
- 已成功阶段不会因后续失败而重复调用。
- 单阶段最多尝试三次。
- UI 首页以瀑布流展示视频卡片和真实处理状态。
- 深度笔记可在原卡片内展开。
- 完整原文进入独立工作台并正确渲染 Markdown。
- 原始字幕入口只能访问受管理视频目录内的文件。
- 忽略后只保留封面、标题和恢复按钮，后台处理及文件不受影响。
- 05:00–11:59 不自动同步，立即同步仍可执行。
- `launchd` 不依赖本地 Web 服务。
- UI 和 `launchd` 同时触发时不会重复处理同一视频。
- 视频移出收藏夹后本地成果仍可访问。
- API Key 和 B 站凭据不会出现在数据库、日志和页面。
- 上下文超限时不会静默截断。
- 实现不包含 Non-goals 明确排除的任何能力。

## Risks

- B 站非官方接口变化可能破坏登录、收藏夹或字幕读取。
- 登录凭据会过期，当前 CLI 还可能尝试读取浏览器 Cookie。
- GPL 依赖可能限制未来公开分发方式。
- 不同 OpenAI-compatible 服务对 `/models`、JSON 输出和错误格式的实现不一致。
- LLM 可能把字幕整理变成改写或删减。
- LLM 可能错误纠正英文专有名词。
- `launchd` 环境变量、PATH 和 Keychain 可见性与交互式终端不同。
- FastAPI 文件读取接口若未限制路径，可能造成任意本地文件读取。
- 不做长文本分块意味着极端长字幕会进入人工处理，而不是自动完成。
- 封面 URL 或下载可能受防盗链、超时和上游变化影响。
- UI 和定时任务并发可能造成重复调用，必须依赖锁和数据库约束。

## Assumptions

- V0 只面向当前 macOS 单用户环境。
- 本地页面只监听 `127.0.0.1`，因此 V0 不实现网页登录。
- API Key 使用 macOS Keychain；若实现时不可行，必须停止并请求批准替代存储方式。
- 字幕最多检查三次，并且不超过首次发现后的 24 小时；先达到任一条件即停止。
- 用户不会依赖手工修改 Markdown 改变页面结构化内容。
- 正式 Python package 名称、根级构建工具和迁移文件路径由实现阶段在现有空白结构中确定，但不得跨越本规格 Change Boundary。

## Stop and Escalation Conditions

后续实现遇到以下情况必须停止并请求决定：

- 规格内部要求发生冲突。
- 需要修改或分叉上游 `bilibili-cli` 才能完成 V0。
- 必须引入新的 B 站 SDK。
- 需要用音频或 ASR 才能满足验收。
- OpenAI-compatible Chat Completions 无法稳定返回可校验结果。
- Keychain 无法满足后台 `launchd` 读取要求，需要改为明文凭据。
- 需要引入队列、Worker、Redis、Docker、SPA 或云服务。
- 必须开放本地 UI 到局域网或公网。
- 许可证问题影响计划中的分发方式。
- 无法保证原始字幕文件访问的路径安全。
- 无法保证 UI 和自动同步的幂等性。
- 任何 Acceptance Criterion 无法满足。
- 实现复杂度明显超出 Complexity Budget。
- 继续工作需要实现 Non-goals。
- 出现新的产品权衡，需要用户接受。
- 工作正在演化为通用 Provider、Agent 或工作流框架。
